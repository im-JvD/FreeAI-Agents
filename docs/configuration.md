# ⚙️ پیکربندی و فایل‌ها

این سند دقیقاً توضیح می‌دهد اسکریپت چه فایل‌هایی می‌سازد، هر بخش چه کاری می‌کند و چطور شخصی‌سازی‌شان کنید. نصاب یک اسکریپت واحد برای **هر دو گیت‌وی** است: **LiteLLM** (داکر) و **OmniRoute** (npm رسمی) — و هر دو با **یک نام مدل مشترک** یعنی `claude-freeagents` سرو می‌شوند.

---

## ۱. نقشهٔ فایل‌های تولیدشده

| فایل / مسیر | سیستم | نقش |
|---|---|---|
| `~/.litellm/config.yaml` | WSL | پیکربندی LiteLLM (model_list + router_settings + …) |
| `~/.litellm/master_key.txt` | WSL | کلید پروکسی LiteLLM و ورود پنل (`600`) |
| `~/.litellm/dashboard_credentials.txt` | WSL | URL و اطلاعات ورود پنل LiteLLM (`600`) |
| `~/.litellm/db_password.txt` + `~/.litellm/pgdata/` | WSL | رمز و دادهٔ Postgres پنل LiteLLM (وقتی `LITELLM_UI_DB=1`) |
| `~/.omniroute/.env` | WSL | secretهای OmniRoute، پورت، مسیر داده و پراکسی (`600`) |
| `~/.omniroute/storage.sqlite` | WSL | دیتابیس OmniRoute (اتصال‌ها، کلیدها، comboها، تنظیمات) |
| `~/.free-ai-agents/` | WSL | state نصاب: `setup.sh` (کپی مدیر)، `provider_keys.env` (`600`)، `windows_proxy.txt` (`600`)، `omniroute_claude.key`، `omniroute_master.key`، `omniroute.pid`، `active_gateway`، `logs/` |
| `~/.free-ai-agents/live_test.sh` | WSL | تست زنده upstream با کلید واقعی — سلامت و چت واقعی هر دو گیت‌وی (حذف با uninstall) |
| `~/.free-ai-agents/omniroute-run.sh` | WSL | لانچر OmniRoute (env را لود و `omniroute serve` را اجرا می‌کند، `700`) |
| `/usr/local/bin/freeagents` | WSL | تنها CLI مدیریت (up/down/status/doctor/…) |
| `/usr/local/bin/freeagents-boot.sh` | WSL | استارت خودکار در بوت WSL (حالت `wslconf`) |
| `/etc/systemd/system/litellm.service` و `omniroute.service` | WSL | استارت خودکار (حالت `systemd`) |
| `/etc/docker/daemon.json` | WSL | میرورهای ایرانی داکرهاب (+ بکاپ قبلی) |
| `/etc/wsl.conf` | WSL | خط `command = /usr/local/bin/freeagents-boot.sh` |
| `%USERPROFILE%\.claude\settings.json` | ویندوز | اتصال Claude Code به گیت‌وی فعال (بلوک `env`) |
| `%LOCALAPPDATA%\Claude-3p\configLibrary\<uuid>.json` | ویندوز | پروفایل گیت‌وی برای اپ Claude Desktop |
| `%LOCALAPPDATA%\Claude-3p\configLibrary\_meta.json` | ویندوز | فهرست پروفایل‌ها + `appliedId` (گیت‌وی فعال) |
| `%LOCALAPPDATA%\Claude-3p\claude_desktop_config.json` | ویندوز | کانفیگ کمکی اپ دسکتاپ |

## ۲. ساختار `config.yaml` (LiteLLM)

نمونهٔ خلاصهٔ خروجی وقتی چند کلید داده باشید:

```yaml
# Free AI Agents - generated by setup.sh v0.0.5
# Single model group 'claude-freeagents' with every configured provider as a
# deployment: LiteLLM load-balances and retries across them.
model_list:
  # ---------------- Groq ----------------
  - model_name: claude-freeagents
    litellm_params:
      model: groq/openai/gpt-oss-120b
      api_key: os.environ/GROQ_API_KEY
      api_base: https://api.groq.com/openai/v1
      drop_params: true
    model_info:
      id: fa-groq-1
      mode: chat
      context_window: 131072
      max_input_tokens: 131072
      max_output_tokens: 32768
  # ---------------- Google AI Studio ----------------
  - model_name: claude-freeagents
    litellm_params:
      model: gemini/gemini-2.5-flash
      api_key: os.environ/GEMINI_API_KEY
      drop_params: true
    model_info: { id: fa-gemini-1, mode: chat, context_window: 1048576, ... }
  # … به ازای هر کلید و هر مدل، یک deployment دیگر در همین گروه

# Router behaviour: if one provider fails or is rate-limited, the next
# deployment in the 'claude-freeagents' group is tried automatically.
router_settings:
  routing_strategy: simple-shuffle
  num_retries: 3
  retry_after: 1
  allowed_fails: 3
  cooldown_time: 30
  timeout: 600
  enable_pre_call_checks: true
  model_group_alias:
    claude-sonnet-4-5:      # سازگاری با کاتالوگ مدل اپ Desktop
      model: claude-freeagents
      hidden: true          # در /v1/models نمایش داده نمی‌شود

litellm_settings:
  drop_params: true
  request_timeout: 600
  num_retries: 2
  json_logs: false

general_settings:
  master_key: os.environ/LITELLM_MASTER_KEY
  trusted_proxy_ranges: []  # بدون هشدار login-throttle
  # وقتی LITELLM_UI_DB=1 باشد، این خط هم اضافه می‌شود:
  # database_url: os.environ/DATABASE_URL
```

### نکات کلیدی

- **همهٔ deploymentها یک `model_name` دارند** (`claude-freeagents`) — کلاینت فقط همین یک نام را می‌بیند و LiteLLM خودش بین ارائه‌دهنده‌ها load-balance می‌کند.
- **`simple-shuffle` + `num_retries` + `cooldown_time`**: اگر یک ارائه‌دهنده خطا بدهد یا rate-limit شود، درخواست خودکار به deployment بعدی می‌رود و ارائه‌دهندهٔ خراب موقتاً از چرخه خارج می‌شود.
- **`model_group_alias`**: اپ Claude Desktop در بعضی نسخه‌ها فقط نام‌های کاتالوگ Anthropic را می‌پذیرد؛ این alias (`claude-sonnet-4-5`) به همان مدل واحد می‌رسد و با `hidden: true` از فهرست `/v1/models` بیرون می‌ماند.
- **`api_key: os.environ/...`**: کلیدها از متغیر محیطی کانتینر خوانده می‌شوند و **هرگز داخل فایل نوشته نمی‌شوند**.
- **`drop_params: true`**: پارامترهای پشتیبانی‌نشدهٔ یک ارائه‌دهنده بی‌صدا حذف می‌شوند تا درخواست به ارائه‌دهندهٔ بعدی نخورد.

## ۳. کلیدها و secretها

| مورد | مسیر | توضیح |
|---|---|---|
| Master Key لایت‌ال‌ال‌ام | `~/.litellm/master_key.txt` | `sk-` + ۶۴ کاراکتر hex؛ هم برای API و هم ورود پنل LiteLLM |
| کلید کلاینت OmniRoute | `~/.free-ai-agents/omniroute_claude.key` | کلید `sk-…` که نصاب از API خود OmniRoute می‌سازد و به Claude می‌دهد |
| کلید مدیریت OmniRoute | `~/.free-ai-agents/omniroute_master.key` | کلید دسترسی مدیریتی (پشتیبان) |
| secretهای OmniRoute | `~/.omniroute/.env` | `JWT_SECRET` (≥۳۲)، `API_KEY_SECRET` (≥۱۶)، `INITIAL_PASSWORD` (≥۸) — بین نصب‌ها حفظ می‌شوند |
| کلیدهای ارائه‌دهنده | `~/.free-ai-agents/provider_keys.env` | برای پیشنهاد «نگه‌داشتن کلیدهای قبلی» در نصب‌های بعدی (`600`) |

- تولید خودکار: JWT/API-KEY با `openssl rand`، master key با `openssl rand -hex 32`.
- دیدن سریع همه‌چیز: `freeagents credentials`
- تغییر دستی secretهای OmniRoute: مقدار را در `~/.omniroute/.env` عوض کنید و `freeagents restart` بزنید (مقادیر کوتاه‌تر از حداقل، سرور را از کار می‌اندازند).

## ۴. اجرای سرویس‌ها

### LiteLLM (داکر)

```bash
sudo docker run -d \
  --name litellm \
  --restart unless-stopped \
  -p 4000:4000 \
  -v ~/.litellm/config.yaml:/app/config.yaml:ro \
  --network litellm-net \
  -e LITELLM_MASTER_KEY="sk-..." \
  -e GROQ_API_KEY="..." \
  ghcr.io/berriai/litellm:main-latest \
  --config /app/config.yaml --port 4000
```

با `LITELLM_UI_DB=1` (پیش‌فرض) یک کانتینر `litellm-db` (Postgres) هم ساخته می‌شود و `DATABASE_URL` به پروکسی داده می‌شود.

### OmniRoute (npm رسمی)

```bash
npm install -g omniroute            # Node ≥ 20 (خودکار از NodeSource)
~/.free-ai-agents/omniroute-run.sh  # لانچر: env را لود و `omniroute serve` را اجرا می‌کند
```

- پورت پیش‌فرض: `20128` (قابل تغییر با `OMNIROUTE_PORT`)
- داده: `DATA_DIR=~/.omniroute`
- پکیج از `npmjs.org` نصب می‌شود و در صورت خطا، خودکار `registry.npmmirror.com` امتحان می‌شود.
- مدیریت: سرویس `omniroute.service` (systemd) یا همان لانچر در حالت `wslconf`.

## ۵. اتصال Claude Code (سمت ویندوز)

نصاب `%USERPROFILE%\.claude\settings.json` را می‌سازد؛ بلوک `env` آن به هر نشست Claude Code تزریق می‌شود:

```json
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://127.0.0.1:4000",
    "ANTHROPIC_AUTH_TOKEN": "sk-...",
    "ANTHROPIC_MODEL": "claude-freeagents",
    "ANTHROPIC_DEFAULT_OPUS_MODEL": "claude-freeagents",
    "ANTHROPIC_DEFAULT_SONNET_MODEL": "claude-freeagents",
    "ANTHROPIC_DEFAULT_HAIKU_MODEL": "claude-freeagents",
    "ANTHROPIC_SMALL_FAST_MODEL": "claude-freeagents",
    "CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY": "1",
    "CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC": "1",
    "CLAUDE_CODE_ATTRIBUTION_HEADER": "0",
    "CLAUDE_CODE_AUTO_COMPACT_WINDOW": "120000"
  }
}
```

| فیلد | توضیح |
|---|---|
| `ANTHROPIC_BASE_URL` | آدرس گیت‌وی فعال — **بدون `/v1`** (Claude Code مسیرهای Anthropic را خودش می‌سازد). WSL2 پورت‌ها را با ویندوز به اشتراک می‌گذارد، پس `127.0.0.1` از ویندوز کار می‌کند |
| `ANTHROPIC_AUTH_TOKEN` | توکن گیت‌وی فعال: در LiteLLM همان Master Key و در OmniRoute کلید `omniroute_claude.key` |
| `ANTHROPIC_MODEL` + سه فیلد `ANTHROPIC_DEFAULT_*` | همه روی مدل واحد `claude-freeagents` تنظیم می‌شوند تا هر انتخاب داخلی کلاد کد به همان مدل برسد |
| `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY` | فهرست مدل‌ها از `GET /v1/models` گیت‌وی خوانده می‌شود (در پیکر `/model` با برچسب «From gateway») |
| `CLAUDE_CODE_AUTO_COMPACT_WINDOW` | پنجرهٔ فشرده‌سازی خودکار (پیش‌فرض `120000`، قابل تغییر با `FREEAGENTS_COMPACT_WINDOW`) |
| `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` | جلوگیری از ترافیک غیرضروری به سرورهای Anthropic |

> 🖥️ **اپ Claude Desktop**: نصاب برای هر گیت‌وی یک پروفایل در `%LOCALAPPDATA%\Claude-3p\configLibrary\<uuid>.json` می‌سازد (LiteLLM: `…a119e`، OmniRoute: `…a110e`)، `_meta.json` را به‌روز می‌کند و گیت‌وی فعال را با `appliedId` نشان می‌دهد. بدون رجیستری و بدون دسترسی ادمین. تعویض گیت‌وی فعال: منو → گزینهٔ `9` (Config Manager) → «Switch the ACTIVE gateway».
>
> اگر از قبل `settings.json` داشته باشید، نصاب آن را در `settings.json.bak.<زمان>` نگه می‌دارد و در حذف نصب، جدیدترین بکاپ برمی‌گردد.

## ۶. پروکسی ویندوز (عبور ترافیک از فیلترشکن ویندوز)

در گام «API keys setup» می‌توانید فعالش کنید (`Route provider traffic through your Windows proxy? [y/N]`). با فعال‌سازی، **ترافیک هر دو گیت‌وی** به ارائه‌دهنده‌ها از برنامهٔ پراکسی ویندوز (Clash / v2rayN / Hiddify / Nekoray) رد می‌شود و تحریم منطقه‌ای Google/Cerebras و… بدون VPN سیستم‌عامل حل می‌شود.

| مورد | مقدار |
|---|---|
| فایل تنظیمات | `~/.free-ai-agents/windows_proxy.txt` (یک خط: `http://IP:PORT`، دسترسی `600`) |
| LiteLLM | `HTTP_PROXY` / `HTTPS_PROXY` / `NO_PROXY` روی کانتینر |
| OmniRoute | همان متغیرها داخل `~/.omniroute/.env` (+ `ALL_PROXY`) |
| Docker pull | اگر پراکسی فعال باشد، اسکریپت `/etc/systemd/system/docker.service.d/http-proxy.conf` را می‌سازد تا `docker pull` از `ghcr.io` هم از پراکسی رد شود (رفع TLS timeout) |
| آدرس پیش‌فرض | IP ویندوز از دید WSL + پورت `7890` |
| تست نصب | یک درخواست واقعی از مسیر پراکسی زده می‌شود (با `FREEAGENTS_KEY_CHECK=0` غیرفعال) |
| نصب دوباره | «Keep the Windows proxy setting?» — Enter = نگه‌داشتن، `n` = تعویض |
| خاموش‌کردن | منو → `9` (Config Manager) → «Proxy mode» → Off (هر دو گیت‌وی ری‌استارت می‌شوند) |

| پنل | آدرس | ورود |
|---|---|---|
| LiteLLM UI | `http://127.0.0.1:4000/ui` | نام کاربری `admin`، رمز = Master Key (`~/.litellm/master_key.txt`) |

- در داشبورد OmniRoute می‌توانید اتصال‌ها، کلیدها و combo `claude-freeagents` را ببینید و مدل‌ها را تست کنید.

## ۸. اجرای خودکار در بوت WSL

دو لایه:

1. LiteLLM: `--restart unless-stopped` روی کانتینر.
2. هر دو گیت‌وی، با یکی از این دو مکانیزم (بسته به `FREEAGENTS_BOOT_MODE`):
   - **systemd** (پیشنهادی، اگر فعال باشد): `litellm.service` و `omniroute.service` — `systemctl status litellm` / `systemctl status omniroute`
   - **boot command** (بدون systemd): خط `command = /usr/local/bin/freeagents-boot.sh` در `/etc/wsl.conf`

> 💡 فعال‌سازی systemd: در `/etc/wsl.conf` بنویسید `[boot]` و `systemd=true`، بعد `wsl --shutdown` بزنید.

اجبار حالت (قبل از اجرا):

```bash
FREEAGENTS_BOOT_MODE=systemd bash setup.sh   # فقط سرویس‌های systemd
FREEAGENTS_BOOT_MODE=wslconf bash setup.sh   # فقط boot command
# پیش‌فرض: auto (تشخیص خودکار)
```

## ۹. دستورات مدیریت (`freeagents`)

| دستور | کار |
|---|---|
| `freeagents` | باز کردن منوی تعاملی (بدون آرگومان) |

## ۱۰. متغیرهای محیطی نصاب

| متغیر | پیش‌فرض | کاربرد |
|---|---|---|
| `FREEAGENTS_BOOT_MODE` | `auto` | `auto` / `systemd` / `wslconf` |
| `FREEAGENTS_SKIP_WINDOWS` | `0` | `1` = نادیده‌گرفتن کامل یکپارچگی ویندوز (تست/محیط لینوکسی) |
| `FREEAGENTS_KEY_CHECK` | `1` | تست زندهٔ کلیدها (`0` = خاموش) |
| `FREEAGENTS_KEY_CHECK_TIMEOUT` | `10` | مهلت هر تست کلید (ثانیه) |
| `FREEAGENTS_COMPACT_WINDOW` | `120000` | مقدار `CLAUDE_CODE_AUTO_COMPACT_WINDOW` |
| `FREEAGENTS_KEEP_NPM` | `0` | `1` = در حذف نصب، پکیج npm حذف نشود |
| `FREEAGENTS_DOCTOR_TIMEOUT` | `45` | مهلت تست زندهٔ مدل‌ها در `doctor` |
| `LITELLM_PORT` | `4000` | پورت پروکسی LiteLLM |
| `LITELLM_IMAGE` | `ghcr.io/berriai/litellm:main-latest` | ایمیج سفارشی |
| `LITELLM_GHCR_MIRROR` | خالی (خودکار: `ghcr.nju.edu.cn`، `ghcr.m.daocloud.io` امتحان می‌شوند) | میرور ghcr (مثلاً `ghcr.nju.edu.cn`) |
| `LITELLM_PULL_RETRIES` | `5` | تعداد تلاش pull قبل از fallback (با backoff افزایشی) |
| `LITELLM_UI_DB` | `1` | `1` = Postgres برای ورود پنل؛ `0` = بدون DB |
| `LITELLM_DB_IMAGE` | `postgres:16-alpine` | ایمیج دیتابیس پنل |
| `OMNIROUTE_PORT` | `20128` | پورت داشبورد/API ام OmniRoute |
| `OMNIROUTE_DATA_DIR` | `~/.omniroute` | مسیر دادهٔ OmniRoute |
| `OMNIROUTE_NPM_PACKAGE` | `omniroute` | نام پکیج npm |
| `OMNIROUTE_FORCE_NPM_INSTALL` | `0` | `1` = نصب مجدد پکیج |
| `OMNIROUTE_MODELS_PER_PROVIDER` | `3` | حداکثر مدل هر ارائه‌دهنده در combo |
| `OMNIROUTE_COMBO_STRATEGY` | `auto` | استراتژی combo |

نمونه:

```bash
LITELLM_GHCR_MIRROR=ghcr.nju.edu.cn OMNIROUTE_PORT=20129 bash setup.sh
```

## ۱۱. شخصی‌سازی‌های رایج

### افزودن مدل جدید به گروه

یک deployment جدید با **همان `model_name: claude-freeagents`** به `model_list` اضافه کنید:

```yaml
  - model_name: claude-freeagents
    litellm_params:
      model: groq/llama-3.1-8b-instant
      api_key: os.environ/GROQ_API_KEY
      api_base: https://api.groq.com/openai/v1
```

سپس:

```bash
sudo docker restart litellm
```

کشف مدل گیت‌وی فعال است، پس مدل جدید خودکار در پیکر `/model` کلاد کد ظاهر می‌شود.

### افزودن ارائه‌دهندهٔ OmniRoute در داشبورد

اگر کلید یک ارائه‌دهنده (مثلاً GitHub Models که در حالت API-key پشتیبانی نمی‌شود) را در داشبورد اضافه کنید، combo را از همان‌جا ویرایش کنید یا دستور `freeagents update` را اجرا کنید تا نصاب دوباره همه‌چیز را بسازد.

### تغییر پورت‌ها

```bash
LITELLM_PORT=4010 bash setup.sh       # نصب مجدد LiteLLM روی پورت جدید
OMNIROUTE_PORT=20129 bash setup.sh    # نصب مجدد OmniRoute روی پورت جدید
```

نصاب، کانتینر/سرویس قبلی را حذف و با پورت جدید بازسازی می‌کند و `settings.json` کلاد کد هم به‌روز می‌شود.

### تعویض گیت‌وی فعال (کلاد کد و دسکتاپ)

منو → `9` (Config Manager) → `5` (Switch the ACTIVE gateway). سپس اپ‌های Claude را کامل ببندید و باز کنید.

### به‌روزرسانی ایمیج LiteLLM

```bash
sudo docker pull ghcr.io/berriai/litellm:main-latest
freeagents update
```
